## User Story
As an operator, I want a health endpoint that reflects database reachability, so that I can detect and react to a database outage automatically.

## Business Value
Operators and orchestrators can tell whether the service is actually able to serve traffic, not just whether the process is running.

## Description
GET /healthz requires no authentication, checks database reachability, and returns 200 when reachable or 503 when not, with a small JSON body describing status.

## Scope
**In:** GET /healthz, unauthenticated; 200 when the database is reachable; 503 when the database is unreachable
**Out:** Structured request logging as a deliverable (SG-11); OpenAPI publication (SG-11)

## Acceptance Criteria
- **E6-S1-AC1** — *Given* a reachable database, *when* fetching `/healthz`, *then* the response is 200.
- **E6-S1-AC2** — *Given* the database is stopped, *when* fetching `/healthz`, *then* the response is 503.
- **E6-S1-AC3** — *Given* `/healthz` is called, *when* the response body is inspected, *then* no authentication was required and the body is JSON describing database status.
