## User Story
As a signed-in member, I want to see my own links on a console page, newest first and paginated, so that I can find and manage what I have created.

## Business Value
A member can see everything they have shortened in one place, newest first, without ever seeing another member's data.

## Description
GET /links returns the signed-in member's own links, newest first, 20 per page, and the console page renders that list. No other member's links are ever included.

## Scope
**In:** GET /links with pagination (20 per page), newest first, scoped to the caller; Console list page rendering the returned links; Empty-state rendering when the member owns zero links
**Out:** Editing a link from the list (SG-2); Any other member's links appearing (SG-5); Click counts, analytics, or export from the list (SG-4, SG-9)

## Acceptance Criteria
- **E4-S1-AC1** — *Given* a member owning 25 links, *when* listing page 1, *then* exactly 20 links are returned, newest first, and none belongs to another user.
- **E4-S1-AC2** — *Given* a member owning 25 links, *when* listing page 2, *then* the remaining 5 links are returned, newest-first order preserved across the page boundary.
- **E4-S1-AC3** — *Given* a member with zero links, *when* opening the console list page, *then* the page renders an empty state with no links and no error.
- **E4-S1-AC4** — *Given* two members who each own links, *when* the second member requests the list endpoint, *then* only the second member's own links appear — never the first member's.
