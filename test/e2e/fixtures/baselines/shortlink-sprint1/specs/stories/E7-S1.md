## User Story
As a developer or evaluator, I want `docker compose up` to bring up the whole stack, so that I can run and test the service without any manual setup or third-party network calls.

## Business Value
Anyone can stand up the entire system from a clean checkout with a single command and no external dependencies, which underpins every other story's ability to be demoed and evaluated.

## Description
A docker-compose.yml brings up the API, web console, and a single Postgres 16 container, reaching healthy from a clean checkout with no image cache, and making no network call to any host outside the compose network at build or run time.

## Scope
**In:** docker-compose.yml with API, web, and exactly one Postgres 16 service; Healthy stack from `docker compose up` on a clean checkout; No outbound network calls at build or run time
**Out:** OpenAPI publication, scheduled purge jobs, and structured request logs as required deliverables (SG-11)

## Acceptance Criteria
- **E7-S1-AC1** — *Given* a clean checkout with no project images cached, *when* `docker compose up` is run once, *then* the stack reaches healthy with exactly one Postgres 16 container.
- **E7-S1-AC2** — *Given* the stack is running, *when* build and runtime network traffic is inspected, *then* no service makes a request to a host outside the compose network.
- **E7-S1-AC3** — *Given* the compose file, *when* it is reviewed, *then* it defines exactly one Postgres 16 service and no other third-party managed service.

### Operations
1. Create `docker-compose.yml` — `backend`, `frontend`, and one `postgres:16` service; healthchecks for each.
2. Create `backend/Dockerfile` — builds the FastAPI app with `uv`.
3. Create `frontend/Dockerfile` — builds the Next.js app with `npm`.
4. Create `.env.example` — `DATABASE_URL`, `PUBLIC_BASE_URL`, `SESSION_COOKIE_NAME`.
5. Verify via `docker compose up` that the stack reaches healthy and no service calls a host outside the compose network, per AC1–AC3.
