## User Story
As a signed-in member, I want to sign out, so that the session cookie I used can no longer authenticate requests.

## Business Value
A member can end their session on a shared or public machine with confidence the old cookie stops working, not just that the browser forgets it.

## Description
POST /auth/sign-out deletes the server-side session record so the previously issued cookie is rejected on the next authenticated request, distinct from a purely client-side cookie clear.

## Scope
**In:** Server-side session invalidation on sign-out; 401 on any authenticated request replaying the invalidated cookie
**Out:** Signing back in (covered by E1-S1)

## Acceptance Criteria
- **E1-S2-AC1** — *Given* a signed-in member, *when* signing out, *then* a subsequent authenticated request returns 401.
- **E1-S2-AC2** — *Given* a signed-in member who has just signed out, *when* the same session cookie from before sign-out is replayed, *then* the request is rejected with 401 rather than succeeding, because the session was invalidated server-side and not merely cleared client-side.
- **E1-S2-AC3** — *Given* a request with no active session, *when* calling sign-out, *then* the response is 401 and no server state changes.
