## User Story
As a signed-in member with many links, I want create and list to stay fast, so that managing a large set of links does not feel slow.

## Business Value
The console and create flow stay responsive as a member accumulates links, instead of degrading as their list grows.

## Description
A load-test harness seeds 100 links for one account via the create endpoint, then samples repeated create and list calls, asserting p95 latency under 300ms for each and emitting a machine-readable report for the evaluator.

## Scope
**In:** Load-test harness seeding 100 links via POST /links; p95 latency measurement for POST /links and GET /links; Machine-readable timing report consumable by /evaluate
**Out:** General-purpose rate limiting (SG-8); Optimizing endpoints other than create/list

## Acceptance Criteria
- **E4-S2-AC1** — *Given* an account holding 100 links, *when* calling the create-link endpoint repeatedly, *then* the p95 response time across the sample is under 300 ms.
- **E4-S2-AC2** — *Given* an account holding 100 links, *when* calling the list endpoint for page 1 repeatedly, *then* the p95 response time across the sample is under 300 ms.
- **E4-S2-AC3** — *Given* the load-test harness, *when* it seeds 100 links and samples both endpoints in one run, *then* it writes a single machine-readable report recording both p95 figures for the evaluator to check.
