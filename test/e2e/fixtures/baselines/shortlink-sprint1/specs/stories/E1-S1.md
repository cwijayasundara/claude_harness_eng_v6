## User Story
As a visitor, I want to register with an email and password and then sign in, so that I receive a session I can use to manage my links.

## Business Value
A member can create an account and prove identity on later visits, which every other capability (create, list, delete) requires as its entry gate.

## Description
POST /auth/register and POST /auth/sign-in issue an HTTP-only session cookie on success. Passwords are hashed with Argon2id before storage and never appear, plaintext or hashed, in any log line the app writes for these two requests.

## Scope
**In:** Register with email + password; Sign in with email + password, receiving an HTTP-only session cookie; Argon2id password hashing at rest; Excluding password/hash bytes from all log output for register and sign-in requests
**Out:** Password reset by email, SSO, or multi-factor authentication (SG-7); Sign-out (owned by E1-S2)

## Acceptance Criteria
- **E1-S1-AC1** — *Given* a registered email and correct password, *when* signing in, *then* the response sets an HTTP-only session cookie and a subsequent authenticated request succeeds.
- **E1-S1-AC2** — *Given* a member registering with a new email and password, *when* the stored credential is read back, *then* it begins with `$argon2id$`.
- **E1-S1-AC3** — *Given* a member registering and then signing in, *when* the application's full log output for those two requests is scanned, *then* it contains neither the plaintext password nor the stored hash.
- **E1-S1-AC4** — *Given* an unregistered email or a wrong password, *when* signing in, *then* the response is 401 and no session cookie is set.
