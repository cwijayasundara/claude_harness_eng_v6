## User Story
As an API caller, I want a clean 503 JSON error when the database is unreachable, so that my client can handle the outage without seeing internal details.

## Business Value
When the database goes down, callers of any endpoint get a clean, predictable error instead of a leaking stack trace or a hang.

## Description
A shared database-reachability check (reused from E6-S1) backs a global error handler: when the database is unreachable, every endpoint other than /healthz returns 503 with a JSON body carrying an `error` field and no stack trace, exception class name, or filesystem path.

## Scope
**In:** Global 503 JSON error envelope for DB-unreachable failures on all endpoints except /healthz; No stack trace, exception class name, or filesystem path in the response body; Recovery to normal status once the database is reachable again
**Out:** Structured request logging as a deliverable (SG-11)

## Acceptance Criteria
- **E6-S2-AC1** — *Given* the Postgres container is stopped, *when* any API endpoint other than `/healthz` is called, *then* the response is 503 with a JSON body carrying an `error` field.
- **E6-S2-AC2** — *Given* the same 503 response, *when* the body is inspected, *then* it contains no stack trace, exception class name, or filesystem path.
- **E6-S2-AC3** — *Given* the database becomes reachable again, *when* the same endpoint is called, *then* the response returns to its normal, non-503 status.
